# Switch UI–Hermes agent integration inventory

This is a starter inventory of **Switch UI source expectations**, not a certified compatibility matrix. It is not exhaustive. Compare these contracts with the exact `Interstellar-code/hermes-agent` fork release and plugin versions under review; endpoint names alone do not establish compatible payloads or behavior. The passing baseline for the current checkout and any agent release is **unknown**: no checks or live integration were run to create this inventory.

## Evidence and interpretation

- **Source evidence** means the cited Switch UI code currently constructs, consumes, or gates a contract. It does not establish that a particular agent release implements it correctly.
- **Focused tests** below are existing candidate tests, not reported results. Tests using mocked fetches, modules, or fake sockets establish behavior against their fixtures, not compatibility with a running agent. Inspect a test before running it and record its result and environment separately.
- **Runtime evidence** requires observing the actual UI and exact agent build together, including relevant responses and user-visible outcomes. Record UI and agent revisions, plugin versions, configuration/topology, test steps, outcomes and failures; redact tokens, prompts and private data. An old source comment describing a live observation is historical context, not evidence for the candidate release.
- Requiredness is unknown unless the cited source explicitly defines a degradation or fallback. Even an optional probe classification is a UI warning policy, not proof that every workflow works without that feature.

## Safe verification boundary

Start with read-only comparison of the exact UI and agent revisions and their endpoint implementations; record unknowns rather than guessing. Focused existing tests can be run separately when authorized, with their fixtures and results identified. For real integration evidence, use disposable state and test data, isolated local endpoints and no real credentials; do not automatically modify the user's agent checkout, configuration, home, services or existing sessions. Obtain explicit approval before state-changing live tests (including chat, session creation/deletion, plugin registration or changes, and configuration writes), and identify cleanup. A VM is not required. Report untested contracts and missing evidence rather than converting a mock pass or a probe into a compatibility claim.
