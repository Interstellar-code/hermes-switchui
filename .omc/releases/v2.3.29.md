# v2.3.29 — Sidebar delete, Telegram sessions, source-tab counts

## Bug Fixes

### Sidebar session delete now refreshes the list
- **Bug:** Deleting a chat/cron session from the sidebar context menu removed
  it on the backend (session count dropped) but the card stayed in the list.
  Clicking it then opened an empty session.
- **Root cause:** The V2 sidebar renders from a separate TanStack Query cache
  (`['sessions-feed','chat','v3-task-split']`) than the delete mutation was
  invalidating (`['chat','sessions']`). The two share no prefix, so removals
  never reached the visible list.
- **Fix:** `sessions-feed.ts` now exports `SESSIONS_FEED_KEY`; the delete
  mutation invalidates it in `onMutate` (optimistic, tombstone-backed),
  `onError` (restore), and `onSuccess` (final). The feed `queryFn` applies
  `filterSessionsWithTombstones` so a deleted card disappears immediately and
  reappears only if the request fails.
- **Also:** the delete dialog no longer unmounts mid-request (cache cleanup
  moved from `onMutate` to `onSuccess`), and gateway-owned sessions (e.g.
  cron) that the dashboard returns 404 for now fall through to the gateway
  DELETE; a 404 is treated as success.

### Telegram sessions now appear in the sidebar
- **Bug:** Telegram sessions were missing from the sessions sidebar and had no
  working filter chip, even though the backend returned them.
- **Root cause:** The feed classified each session by **key-prefix**
  (`cron_`, `api-`). Telegram keys are timestamp-prefixed, so 76 telegram
  rows fell into the generic `chat` bucket. The `source` field was stripped by
  `normalizeSessions`, and the `tg` chip was hidden by a stub feed reporting
  `available: false`.
- **Fix:** The feed now classifies by the authoritative gateway `source`
  field (`telegram → tg`, with key-prefix as fallback); `source` is preserved
  through `normalizeSessions` and typed on `SessionMeta`; the TELEGRAM chip
  shows whenever it has items. Telegram sessions get their own rail color and
  are filterable.

## Changes

### Chat meta bar slimmed; source tabs show counts
- Removed the redundant total-token field (the context-window ring below the
  composer already shows it) and the api-call count from the chat meta bar.
- The chat source tabs now display per-tab counts: messages under **chat**,
  tool invocations under **tool**, skill invocations under **skills**. Skill
  count uses a shared `countSkillEntries` helper so the badge and the skills
  tab always agree.
