# v2.3.28 — Chat State Architecture Consolidation

## Track 1: Reliability (user-facing bug fixes)

### Phase 1.1 — SSE-desync drain stall fix
- **Bug:** The message queue drains on `isComposerLoading` falling edge. A
  dropped SSE completion event leaves busy signals stuck forever → queue
  never drains (up to 120s waiting TTL, longer if other signals stick).
- **Fix:** New `useDrainWatchdog` escape hatch. Arms only when busy + queued;
  on 5s SSE silence, polls `GET /api/sessions/:sk/active-run` (liveness
  authority). Recoverable snapshot → wait (genuinely live). Not-recoverable →
  releases busy state. Never dequeues directly (prevents double-send).
- **Fence-clean:** zero history→busy coupling. R5 honored (timer alone never
  releases busy; only a not-recoverable snapshot does).

### Phase 1.2 — Liveness-authoritative recovery + interrupted affordance
- **Bug:** Phantom "thinking" bubble when recovering after SSE disconnect.
  History-based predicate could falsely set busy → self-lock.
- **Fix:** Rewrote `useActiveRunCheck` mount logic to snapshot-first
  (liveness = authority). History predicate (`hasUnansweredLatestUserTurn`)
  is now clear-only: it can force `interrupted` (non-busy terminal) or
  `complete` (idle), but NEVER set/sustain streaming. F1 guard
  (`latestTurnIsToolOnly`) prevents false recovery on tool-only completions.
- **UI:** "Run may have continued server-side — resend?" banner (button-only,
  no auto-resend — avoids duplicate runs).
- **Feature flag:** `localStorage.switchui:recovery-reconcile-v1=0` reverts
  to legacy snapshot-only behaviour without deploy.

### Portable persistence (STEP 0)
- **Bug:** Portable conversations vanished on reload. The gateway already
  persists `/v1/chat/completions` to `state.db` — SwitchUI was sending
  `X-Claude-Session-Id` but the gateway reads `X-Hermes-Session-Id`.
- **Fix:** Header name corrected in `openai-compat-api.ts`. No new endpoint
  needed.

## Track 2: Sustainability (maintainability, no bug urgency)

### Phase 2.1 — runPhase state machine
- New `run-phase.ts` module: `idle → sending → streaming → complete | error | interrupted`
- **Fence-enforced:** Reducer rejects `predicate-clear → streaming/sending`
  (F2 guard). History can never feed busy logic.
- `selectIsComposerBusy` replaces the 6-signal `isChatRuntimeBusy`
  composition with a single store selector.

### Phase 2.3 — runPersistence adapter + queue migration
- **F4 pre-mortem guard:** All chat-run sessionStorage/localStorage I/O in
  one policy-free adapter (`run-persistence.ts`). No conditionals, no
  business logic — just I/O.
- **R3/Q1:** Message queue moved from localStorage to sessionStorage
  (tab-scoped, no cross-tab double-send). One-time per-client migration:
  drain localStorage entries into sessionStorage on first read, clear
  localStorage, set `switchui:queue-migrated-to-sessionstorage-v1=1` flag.
- All keys byte-identical to legacy for rollback safety. TTLs preserved:
  `claude_streaming_` (60s), `claude_recovery_msg_` (5min), `claude_waiting_` (120s).

## Architecture decisions
- SwitchUI permanently owns busy-input policy (client FIFO). Hermes native
  queue/busy_input_mode intentionally unused over REST. (ADR in plan doc.)
- Recovery cannot restore busy across SwitchUI restart (A1 limitation —
  surfaced as `interrupted`, not phantom).
- Multi-run-per-session recovery out of scope (F3, single-run only).
