# v2.5.19 — Profile-scoped Self-Improve metrics

**Released:** 2026-07-19
**Type:** patch (Self-Improve feature)

## Problem

Self-Improve metrics were collected under a single global `profile="(unknown)"` placeholder (P0, #133-Q1). The screen had a profile picker, but `collect` ignored it — one agent profile's error/warn/cost stats could not be told apart from another's.

## Fix

Frontend for real per-profile collection, paired with the backend in `karpathy-self-improve` (Interstellar-code/hermes-agent#174):

- `collectMetrics` / `triggerCollect` now require a profile and POST a `{profile}` body.
- New `getProfileStatus` / `fetchProfileStatus` + `ProfileStatus` type and route `profiles.$profile.ts` (`GET /api/self-improve/profiles/{profile}`).
- Metrics POST route parses and validates the profile (`400` on missing/blank/invalid JSON).
- Screen: profile-gated queries, `selectAvailableProfile` default, Escape-closes-dialog, negative-cost formatting, focus-visible a11y, responsive layout.

## Dependency

Requires hermes-agent#174 deployed first — without the per-profile backend, `collect` and profile-status calls return 503.
